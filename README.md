# MOSS-Image Speed Boost for Forge Neo

Makes MOSS-Image in Forge Neo about 2.4x faster per DiT pass — the same speed as ComfyUI's native MOSS-Image. It runs
the DiT blocks of [moss-image-forge-neo](https://github.com/eduardoabreu81/moss-image-forge-neo) on the fused
comfy_kitchen kernels that ComfyUI uses; the CUDA profile matches ComfyUI kernel for kernel.

Requires the **moss-image-forge-neo** extension. Other models are not affected.

## Installation

1. Install [moss-image-forge-neo](https://github.com/eduardoabreu81/moss-image-forge-neo) and check that MOSS-Image
   generates.
2. In Forge Neo, open **Extensions → Install from URL**, paste
   `https://github.com/EterniteSp/MOSS-Image-Speed-Boost` and click **Install**.
3. For Fused SiTU, update comfy-kitchen to 0.2.39 or newer (see [comfy-kitchen 0.2.39+](#comfy-kitchen-0239)).
4. Restart Forge. The console prints `[MOSS-Image Speed Boost] MOSS-Image blocks can run on comfy_kitchen kernels`.

Tested on Forge Neo 2.30 (neo branch, October 2026) with moss-image-forge-neo 0.1.2, torch 2.13 + CUDA 13.0 and an
RTX 4070 (Ada). INT8 attention needs a GPU that comfy_kitchen supports for it; otherwise the option has no effect.

## Forge Neo with native MOSS-Image support

Forge Neo builds from 2026-10-21 onward (commit `be6fa5d4`) load MOSS-Image natively, without moss-image-forge-neo.
**This extension does not apply to that native model, and native users don't need it:**

- The native model (`backend/nn/moss_image.py`) is a port of ComfyUI's MOSS-Image and already uses the same fused
  kernels: `rms_adaln`, `rms_rope_split_half` and Fused SiTU (`linear_input_act(..., "situ")`).
- INT8 attention is there too, but only through the launch flag `--use-ck-attention`, which switches attention for
  every model, not just MOSS-Image.

So native MOSS-Image runs like this extension with **Fused SiTU** on, and with **INT8 attention** on when
`--use-ck-attention` is set. What the extension adds on top is per-generation control of the two options, recorded
in the infotext.

The extension patches only moss-image-forge-neo's DiT. When an image is generated by the native model, it does
nothing and writes nothing to the infotext. If moss-image-forge-neo is not installed, the accordion is hidden.

Reasons to stay on moss-image-forge-neo with this extension, as of 2026-10-24:

- The official uncond recipe (skip block 22 on the negative pass) exists only in moss-image-forge-neo.
- So does the "MOSS" scheduler (the upstream pipeline's time-shifted grid).

Native support has had LoRAs for fused q/k/v checkpoints since 2026-10-23.

## Usage

The **MOSS-Image Speed Boost** accordion appears in txt2img and img2img.

- **Checkbox in the accordion header** turns the boost on. Off = the MOSS-Image extension's own code path.
- **INT8 attention** — quantized attention instead of bf16 SDPA.
- **Fused SiTU** — the SiTU activation folded into the INT8 quantization of `ffn_down`. Needs comfy-kitchen 0.2.39
  or newer (Forge Neo 2.30 ships 0.2.37, see below).

The settings apply per generation and are written to the infotext, for example
`MOSS Speed Boost: on, INT8 attention, Fused SiTU` or `MOSS Speed Boost: off`. PNG Info and "Read generation
parameters" restore them, so any image can be reproduced exactly.

## Speed

RTX 4070, MOSS-Image SFT INT8 ConvRot, 832×1248.

| Mode | 8 steps, CFG 1, ER SDE | 50 steps, CFG 3, Euler |
| --- | --- | --- |
| Boost off | 1.17 it/s | 82 s |
| Boost on, both options off | 1.80 it/s | 53 s |
| Boost on + Fused SiTU | 2.22 it/s | 42 s |
| Boost on + INT8 attention | 2.15 it/s | 45 s |
| Boost on + both options | **2.80 it/s** | **34 s** |
| ComfyUI, for reference | 2.95 it/s | — |

## How the image changes

No mode reproduces the boost-off image pixel for pixel. Each kernel rounds bf16 in a different order, and a few
denoising steps amplify that into visible differences: the size of the sun, a cloud's tint, small objects. All modes
stay equally close to the original on average (PSNR on 10 test scenes), and "everything on" is as close as any.

Because each combination gives a slightly different image at the same seed, switching options is also a cheap way to
get close alternatives of an image you like.

| What is replaced | With |
| --- | --- |
| RMSNorm + adaLN modulation, several ops | `ck.rms_adaln`, one kernel |
| q/k head RMSNorm + RoPE, ~10 ops, bf16 RoPE table | `ck.rms_rope_split_half`, one kernel, fp32 table |
| bf16 SDPA attention | `ck.int8_attention` (INT8 attention) |
| SiTU, 6 elementwise ops over a 2×8192-wide tensor | `int8_linear(..., input_act="situ")` (Fused SiTU) |
| gated residuals with temporaries | second residual in place |

Unchanged: the text blocks, the block-22 skip of the negative pass, LoRA, offloading and the INT8 matmuls. If
`ffn_down` holds a non-INT8 weight (online LoRA in "fp16 LoRA" mode), Fused SiTU falls back to the eager activation
with an identical result. Nothing is changed on disk; the patch is applied in memory at startup.

## comfy-kitchen 0.2.39+

Forge Neo 2.30 ships comfy-kitchen 0.2.37; upstream Forge Neo has since moved to 0.2.40. Forge only checks for a
minimum version at startup, so a newer one stays installed:

```
"<Forge Neo>\venv\Scripts\python.exe" -m pip install comfy-kitchen==0.2.40 --no-deps
```

Tested after the upgrade at fixed seeds: SDXL (fp16), Chroma (fp8), Qwen-Image 2.1 (INT8), Z-Image Turbo (INT8, with
and without online LoRA) and Z-Image (fp8) are byte-identical to 0.2.37, at the same speed. To go back:
`pip install comfy-kitchen==0.2.37`.

## Uninstall

Delete the extension's folder under `extensions` and restart Forge. If the MOSS-Image extension changes its DiT
block in an update, the boost disables itself at startup with a console message instead of breaking generation.
